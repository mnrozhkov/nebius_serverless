# Python SDK Example Comparison: Nebius vs. Modal vs. RunPod

This document compares the developer experience of four SDK tracks across two containerized GPU tasks:

1. **Official Nebius SDK** (`nebius==0.6.27`) — [`examples/benchmark/nebius/`](nebius/)
2. **Designed Nebius SDK** (`nebius_serverless`) — reuses existing product examples [`examples/job_quickstart.py`](../job_quickstart.py) and [`examples/train/axolotl_lora.py`](../train/axolotl_lora.py) directly without duplicating code
3. **Modal** (`modal==1.6.3`) — [`examples/benchmark/modal/`](modal/)
4. **RunPod** (`runpod==2.0.0rc1`) — [`examples/benchmark/runpod/`](runpod/)

### Why Containerized Workloads Only (`job_quickstart.py` + `axolotl_lora.py`)?

- **No inline `worker` strings in Python:** Passing a multi-line `WORKER` Python string via `python -c` is unnatural when comparing against Modal and RunPod, where developers expect `@app.function` or `@app.task` decorators to run Python functions directly. The [proposed decorator sketches](#proposed-decorator-sketches-not-implemented) show that shape from [`docs/decorators.md`](../../docs/decorators.md). They are not implemented.
- **Sugar on top of the Nebius SDK for containerized jobs:** The current `nebius_serverless` Cloud Jobs slice operates on containerized command workloads (`["nvidia-smi"]`, `["bash", "-lc", "axolotl train ..."]`). Comparing `job_quickstart.py` and the Axolotl fine-tuning job (with S3 / Volume model artifact persistence) measures the exact abstraction boundary this slice provides.

All line counts and SHA-256 file snapshots below are reproducibly generated by [`examples/benchmark/measure.py`](measure.py) (`uv run python examples/benchmark/measure.py`).

## Panel 1: Customer Value

**Customer value proposition:** *Run existing containerized GPU workloads on Nebius with less cloud integration work, from a first diagnostic command to a multi-hour fine-tuning job that persists model artifacts to Object Storage.*

### Tasks and Success Conditions

1. **Quickstart (`nvidia-smi`)** — Execute `nvidia-smi` remotely on one requested H100 GPU, wait for completion, and print the final job record.
   - *Nebius success milestone:* `run.wait()` returns and `run.display()` prints the terminal state. Container stdout is inspected separately via `nebius ai job logs <id>`.
   - *Modal and RunPod milestone:* Remote function returns non-empty `nvidia-smi` stdout directly to the caller.
2. **Fine-tuning (`axolotl train` + model artifact persistence)** — Run `axolotl train /workspace/data/config.yaml` on `docker.io/axolotlai/axolotl:main-20260309-py3.11-cu128-2.9.1` on an H100 GPU with a 500 GiB disk, a 24-hour deadline, and persistent storage mounts for `/workspace/data` and `/workspace/artifacts` so the resulting fine-tuned model is saved to S3 / cloud volume.

| Customer need | Work exposed in the Official Nebius SDK (`nebius==0.6.27`) | Designed Nebius SDK (`nebius_serverless`) experience | Evidence demonstrated |
| --- | --- | --- | --- |
| Run my existing command on a GPU. | Load `Config()`, read `parent_id`, initialize `SDK`, instantiate `JobServiceClient`, construct `CreateJobRequest`, `ResourceMetadata`, `JobSpec`, `JobSpec.DiskSpec`, and specify `platform="gpu-h100-sxm"`, `preset="1gpu-16vcpu-200gb"`, `shm_size_bytes`, and `size_bytes`. | Express command, image, `gpu="h100"`, and `timeout="1h"` on `ns.Job(...)` and call `.create()`. | Identical resolved Nebius request settings in `eu-north1`; platform, preset, disk (250 GiB), and `/dev/shm` (16 GiB) resolution move into the SDK. |
| Know whether my work finished successfully. | Wait on the create operation (`operation.wait()` + `operation.sync_wait()`), extract `operation.resource_id`, loop on `client.get(GetJobRequest(id=job_id)).wait()`, check `TERMINAL_STATES`, sleep between polls, and close the SDK in `finally: sdk.sync_close()`. | Call `run.wait()` and `run.display()`. | Polling loop, terminal-state set, operation waiting, and client teardown move out of customer code. |
| Configure spot fine-tuning and save model artifacts to S3. | POSIX-quote arguments with `shlex.quote`, set `preemptible=True` + `PricingModelSpec(follows_spot_price=FollowsSpotPriceSpec())`, convert `500Gi` and `24h` to raw bytes/seconds, and build `JobSpec.VolumeMount` protobuf objects with `Mode.READ_ONLY` / `Mode.READ_WRITE`. | Pass `pricing="spot"`, `disk="500Gi"`, `timeout="24h"`, and `volumes=["s3://axolotl-data:/workspace/data:ro", "s3://axolotl-artifacts:/workspace/artifacts:rw"]`. | Orchestration drops from 85 lines to 16 lines (81.2% reduction) and total Python drops from 88 lines to 19 lines (78.4% reduction). |
| Adapt the example to my workload. | Locate the corresponding nested protobuf fields across `JobSpec`, `DiskSpec`, `PricingModelSpec`, and `VolumeMount`. | Edit top-level `Job(...)` arguments (`command`, `image`, `gpu`, `timeout`, `volumes`, `disk`, `pricing`). | Measured via the follow-up adaptation protocol in Panel 6 (`Pending study`). |

#### Before — Official Nebius SDK (`examples/benchmark/nebius/quickstart.py`, 58 orchestration lines / 61 total lines)

```python
import time
from datetime import timedelta
from uuid import uuid4

from nebius.aio.cli_config import Config
from nebius.api.nebius.ai.v1 import (
    CreateJobRequest,
    GetJobRequest,
    JobServiceClient,
    JobSpec,
)
from nebius.api.nebius.common.v1 import ResourceMetadata
from nebius.api.nebius.compute.v1 import DiskSpec as ComputeDisk
from nebius.sdk import SDK

TERMINAL_STATES = frozenset(
    {"COMPLETED", "FAILED", "CANCELLED", "ERROR"}
)
POLL_SECONDS = 1.0

# Inside main():
config = Config()                                      # SDK reads CLI profile
project_id = config.parent_id
if not isinstance(project_id, str) or not project_id.strip():
    raise RuntimeError("Nebius profile has no parent_id configured")
sdk = SDK(config_reader=config, parent_id=project_id)  # SDK manages lifecycle
try:
    client = JobServiceClient(sdk)
    request = CreateJobRequest(                        # SDK builds request
        metadata=ResourceMetadata(
            parent_id=project_id,
            name=f"job-{uuid4().hex[:12]}",            # SDK generates name
        ),
        spec=JobSpec(
            image="nvidia/cuda:13.1.1-runtime-ubuntu24.04",
            container_command="nvidia-smi",
            platform="gpu-h100-sxm",                   # SDK resolves gpu="h100"
            preset="1gpu-16vcpu-200gb",
            timeout=timedelta(seconds=3600),           # SDK parses timeout="1h"
            shm_size_bytes=16 * 1024**3,               # SDK applies 16Gi default
            disk=JobSpec.DiskSpec(                     # SDK applies 250Gi default
                type=ComputeDisk.DiskType.NETWORK_SSD,
                size_bytes=250 * 1024**3,
            ),
        ),
    )
    operation = client.create(request).wait()          # SDK awaits acceptance
    operation.sync_wait()
    job_id = operation.resource_id
    if not isinstance(job_id, str) or not job_id:
        raise RuntimeError("Create operation returned no job ID")
    print(job_id)
    while True:                                        # SDK polls GetJob
        job = client.get(GetJobRequest(id=job_id)).wait()
        state = job.status.state.name
        if state in TERMINAL_STATES:
            break
        time.sleep(POLL_SECONDS)
    if state != "COMPLETED":
        raise RuntimeError(f"{job_id}: {state}")
finally:
    sdk.sync_close()                                   # SDK closes transport
```

*What the excerpts omit:* Module/function docstrings.

#### Modal (`examples/benchmark/modal/quickstart.py` — 8 orchestration lines, 10 workload lines, 18 total Python lines)

```python
import subprocess
import modal

app = modal.App("nebius-comparison-quickstart")

@app.function(gpu="H100!", timeout=3600)
def run_nvidia_smi() -> str:
    completed = subprocess.run(
        ["nvidia-smi"], check=True, text=True, stdout=subprocess.PIPE
    )
    return completed.stdout

@app.local_entrypoint()
def main() -> None:
    output = run_nvidia_smi.remote()
    if not output.strip():
        raise RuntimeError("nvidia-smi returned empty output")
    print(output, end="")
```

#### RunPod (`examples/benchmark/runpod/quickstart.py` — 8 orchestration lines, 12 workload lines, 20 total Python lines)

```python
import subprocess
import runpod

app = runpod.App("nebius-comparison-quickstart")

@app.queue(gpu="H100", execution_timeout_ms=3600000)
def run_nvidia_smi() -> str:
    completed = subprocess.run(
        ["nvidia-smi"], check=True, text=True, stdout=subprocess.PIPE
    )
    return completed.stdout

@runpod.local_entrypoint
def main() -> None:
    output = run_nvidia_smi.remote()
    if not isinstance(output, str) or not output.strip():
        raise RuntimeError("nvidia-smi returned empty output")
    print(output, end="")
```

### Key Cross-Platform Differences (Quickstart)

- **Command recipe vs. remote Python function:** `nebius_serverless` runs `["nvidia-smi"]` directly as the container command (`13` total Python lines in `examples/job_quickstart.py`) without needing a `subprocess.run` wrapper inside Python, whereas Modal (`18` lines) and RunPod (`20` lines) wrap `subprocess.run(["nvidia-smi"])` inside a decorated Python function.
- **Completion status vs. returned stdout:** Modal and RunPod return `nvidia-smi` stdout directly to the caller in Python. Nebius confirms completion in Python and uses `nebius ai job logs <id>` to inspect container stdout.

```python
import shlex
import time
from datetime import timedelta
from uuid import uuid4

from nebius.aio.cli_config import Config
from nebius.api.nebius.ai.v1 import (
    CreateJobRequest,
    FollowsSpotPriceSpec,
    GetJobRequest,
    JobServiceClient,
    JobSpec,
    PricingModelSpec,
)
from nebius.api.nebius.common.v1 import ResourceMetadata
from nebius.api.nebius.compute.v1 import DiskSpec as ComputeDisk
from nebius.sdk import SDK

TERMINAL_STATES = frozenset(
    {"COMPLETED", "FAILED", "CANCELLED", "ERROR"}
)
POLL_SECONDS = 1.0

# Inside main():
config = Config()
project_id = config.parent_id
if not isinstance(project_id, str) or not project_id.strip():
    raise RuntimeError("Nebius profile has no parent_id configured")
sdk = SDK(config_reader=config, parent_id=project_id)
try:
    client = JobServiceClient(sdk)
    args = " ".join(
        shlex.quote(part)
        for part in ("-lc", "axolotl train /workspace/data/config.yaml")
    )
    request = CreateJobRequest(
        metadata=ResourceMetadata(
            parent_id=project_id,
            name=f"job-{uuid4().hex[:12]}",
        ),
        spec=JobSpec(
            image=(
                "docker.io/axolotlai/axolotl:"
                "main-20260309-py3.11-cu128-2.9.1"
            ),
            container_command="bash",
            args=args,
            platform="gpu-h100-sxm",
            preset="1gpu-16vcpu-200gb",
            timeout=timedelta(seconds=24 * 3600),
            shm_size_bytes=16 * 1024**3,
            disk=JobSpec.DiskSpec(
                type=ComputeDisk.DiskType.NETWORK_SSD,
                size_bytes=500 * 1024**3,
            ),
            preemptible=True,
            pricing_model=PricingModelSpec(
                follows_spot_price=FollowsSpotPriceSpec(),
            ),
            volumes=[
                JobSpec.VolumeMount(
                    source="s3://axolotl-data",
                    container_path="/workspace/data",
                    mode=JobSpec.VolumeMount.Mode.READ_ONLY,
                ),
                JobSpec.VolumeMount(
                    source="s3://axolotl-artifacts",
                    container_path="/workspace/artifacts",
                    mode=JobSpec.VolumeMount.Mode.READ_WRITE,
                ),
            ],
        ),
    )
    operation = client.create(request).wait()
    operation.sync_wait()
    job_id = operation.resource_id
    if not isinstance(job_id, str) or not job_id:
        raise RuntimeError("Create operation returned no job ID")
    print(job_id)
    while True:
        job = client.get(GetJobRequest(id=job_id)).wait()
        state = job.status.state.name
        if state in TERMINAL_STATES:
            break
        time.sleep(POLL_SECONDS)
    if state != "COMPLETED":
        raise RuntimeError(f"{job_id}: {state}")
finally:
    sdk.sync_close()
```

## Proposed decorator sketches (not implemented)

These sketches use only the names and calls in [`docs/decorators.md`](../../docs/decorators.md). That file is a proposal for discussion. Nothing in it is in the package. The measured tracks above stay `ns.Job(...).create()` and `run.wait()`. These sketches are not files in this repository, and [`measure.py`](measure.py) does not count them.

A decorator builds a job or an endpoint. It does not add a third cloud object. `@app.job` runs the function once and returns its value. `@app.endpoint` keeps a process up and calls the function on each HTTP request. Decorating a function does not authenticate, upload, or create. The cloud call is `create` on the decorated function.

The contract does not define `@app.function`, `@app.task`, `@app.local_entrypoint`, or `.remote()`. A direct call such as `run_nvidia_smi()` raises `ValidationError` and names `create` and `local`. `local` runs the function in this process and does not check the image or the GPU.

### Quickstart — one function, one job

Same task as Panel 3: run `nvidia-smi` on one H100 and return the command output to the caller. The image is the same CUDA image as [`examples/job_quickstart.py`](../job_quickstart.py). The image supplies Python. This client does not install packages into it.

```python
import subprocess

import nebius_serverless as ns

app = ns.App("nebius-comparison-quickstart")


@app.job(
    image="nvidia/cuda:13.1.1-runtime-ubuntu24.04",
    gpu="h100",
    timeout="1h",
)
def run_nvidia_smi() -> str:
    completed = subprocess.run(
        ["nvidia-smi"],
        check=True,
        text=True,
        stdout=subprocess.PIPE,
    )
    return completed.stdout


if __name__ == "__main__":
    run = run_nvidia_smi.create()
    output = run.result()
    if not isinstance(output, str) or not output.strip():
        raise RuntimeError("nvidia-smi returned empty output")
    print(output, end="")
```

`create` uploads the directory that contains this module, starts one job, and returns a `Run`. `result` waits until that job is terminal, then returns the function value. `create(dry_run=True)` returns the create description and does not upload or create. A second `create` starts another job.

```python
    timeout="24h",
    volumes=[
        "s3://axolotl-data:/workspace/data:ro",
        "s3://axolotl-artifacts:/workspace/artifacts:rw",
    ],
)
def train() -> dict:
    subprocess.run(
        ["bash", "-lc", "axolotl train /workspace/data/config.yaml"],
        check=True,
    )
    return {"artifacts": "/workspace/artifacts"}


if __name__ == "__main__":
    run = train.create()
    print(run.id, run.result())
```

`run.result()` returns that dictionary. If `train` raises, `result` raises `RemoteError` with the exception type name, the message, and `run_id`, after the job is terminal. `result` on a command `Run` from `ns.Job` or `ns.jobs.get` raises `UnsupportedFeature` and tells the caller to use `wait`.

The function must be defined at module level in a file Python can import by module name. Decoration rejects a lambda, a nested function, a method, a function in `__main__` with no file, and a notebook cell.

### Endpoint decorator

`@app.endpoint` is the other decorator in the same contract. It is not a substitute for the quickstart or the fine-tuning job. `create` takes no function arguments and returns a `Service`. Each HTTP `POST` sends a JSON object whose keys are the parameter names. `delete` is what stops billing.

```python
@app.endpoint(
    image="python:3.12-slim",
    gpu="l40s",
    port=8000,
    auth="token",
)
def predict(text: str) -> dict:
    return {"n": len(text)}


service = predict.create()
record = service.wait()
print(service.url, service.token, record["status"]["state"])
service.delete()
```

### What the contract changes relative to the measured Nebius tracks

| Customer problem in the measured tracks | What [`docs/decorators.md`](../../docs/decorators.md) specifies |
| --- | --- |
| A Python function has to be passed as a container command. | `@app.job` uploads the function's module directory (or `App(source=...)`) and runs it from `/workspace`. The upload excludes `.git`, `.venv`, `__pycache__`, and `*.pyc`. File injection is not the transport. |
| `nvidia-smi` and training logs are read with `nebius ai job logs <id>`. | A job function can return a JSON value, such as the `nvidia-smi` stdout string. `result` does not stream logs. |
| Modal `.remote()` and RunPod `.remote()` are one blocking call. | The contract has no `.remote()`. The call is `create`, then `result`. Each `@app.job` create starts a new job. |

The image still has to contain the interpreter and the libraries the function imports, including Axolotl. The client does not build that image and does not install the local environment into it.

## Panel 6: Product Implications and Next Priorities

### 1. What the Current Cloud Jobs Slice Already Solves for Containerized Workloads

- **82.8% reduction in quickstart orchestration (58 → 10 lines)** and **81.2% reduction in fine-tuning orchestration (85 → 16 lines)** by moving profile resolution, regional GPU alias mapping (`gpu="h100"` → `gpu-h100-sxm` / `1gpu-16vcpu-200gb`), spot pricing specs (`pricing="spot"`), disk/timeout unit parsing (`disk="500Gi"`, `timeout="24h"`), POSIX command quoting, S3 volume mount parsing (`s3://bucket:/path:mode`), operation acceptance waiting, and `GetJobRequest` polling into `ns.Job` and `ns.Run`.
- **Direct container-command ergonomics:** When running pre-built container images like `nvidia/cuda` or `axolotlai/axolotl`, `nebius_serverless` (`13` lines for quickstart, `19` lines for Axolotl fine-tuning) is even shorter than Modal (`18` and `27` lines) and RunPod (`20` and `23` lines), which require wrapping CLI commands inside `subprocess.run(...)` inside decorated Python functions.

### 2. Where Customer Friction Remains Visible

- **Log streaming from Python:** Inspecting `nvidia-smi` or `axolotl train` stdout/stderr still requires switching from Python to `nebius ai job logs <id>`.
- **Python function workloads:** When a developer wants to run a local Python function rather than a container CLI command, Modal (`@app.function`) and RunPod (`@app.queue` / `@app.task`) serialize and run the Python function directly. The [proposed decorator sketches](#proposed-decorator-sketches-not-implemented) show `@app.job` and `Run.result` from [`docs/decorators.md`](../../docs/decorators.md). That surface is not implemented.

### 3. Future / Proposed SDK Capabilities (Separate Prototypes)

- **Proposed — Decorators (`@app.job` and `@app.endpoint`):** The sketches above are the contract's spelling. `@app.job` plus `create` and `result` would run a module-level function and return a JSON value. `@app.endpoint` would keep one process up for HTTP `POST` calls. Neither decorator is in `nebius_serverless`. The call is not `.remote()`.
- **Proposed — Log retrieval / streaming in Python:** Fetching or streaming container logs directly from `run` without shelling out to `nebius ai job logs <id>`.

### 4. Onboarding and Adaptation Study Protocol (`Pending study`)

1. **First-run timing (two cohorts: unconfigured account vs. pre-configured credentials/storage):** Record time to accepted execution, time to confirmed completion, and time to verified output (`nebius ai job logs <id>` for quickstart; saved model artifacts in `s3://axolotl-artifacts` for fine-tuning).
2. **Adaptation task:** Ask participants to modify both Official and Designed Nebius scripts to change the training config path, disk size, or GPU type, recording lines changed, completion time, documentation lookups, and failed attempts.

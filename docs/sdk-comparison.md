## Panel 1: Customer Value

**Customer value proposition:** *Run existing workloads on Nebius with less integration work, and reuse that simpler workflow when processing more inputs.*

### Tasks and Success Conditions

1. **Quickstart (`nvidia-smi`)** — Execute `nvidia-smi` remotely on one requested H100 GPU, expose the execution identifier where the platform provides one, wait for completion, and fail unless the execution succeeded.
   - *Nebius success milestone:* `status.state == "COMPLETED"`. Container stdout is inspected separately via `nebius ai job logs <id>`.
   - *Modal and RunPod milestone:* Remote function/handler returns non-empty `nvidia-smi` stdout directly to the caller. These are distinct milestones and are kept explicit below.
2. **Batch GPU Matrix Multiplication (`1024`, `2048`, `4096`)** — Submit all three square matrix sizes before waiting (or invoke the platform's parallel mapping/spawning API), run the identical seeded float32 CUDA workload (`torch.backends.cuda.matmul.allow_tf32 = False`, `torch.set_float32_matmul_precision("highest")`, 3 warm-ups, 10 timed CUDA-event repeats, deterministic 2×2 check, and 9 sampled float64 reference checks with `rtol=1e-4`, `atol=1e-3`), validate every returned summary locally (`schema_version == 1`, matching `size`, non-empty `gpu`, finite positive `elapsed_ms`, finite `mean`, `verified is True`), and print one summary row per size.

| Customer need | Work exposed in the Official Nebius SDK (`nebius==0.6.27`) | Designed Nebius SDK (`nebius_serverless`) experience | Evidence demonstrated |
| --- | --- | --- | --- |
| Run my existing command on a GPU. | Load `Config()`, read `parent_id`, initialize `SDK`, instantiate `JobServiceClient`, construct `CreateJobRequest`, `ResourceMetadata`, `JobSpec`, `JobSpec.DiskSpec`, and specify `platform="gpu-h100-sxm"`, `preset="1gpu-16vcpu-200gb"`, `shm_size_bytes`, and `size_bytes`. | Express command, image, `gpu="h100"`, and `timeout="1h"` on `ns.Job(...)` and call `.create()`. | Identical resolved Nebius request settings in `eu-north1`; platform, preset, disk (250 GiB), and `/dev/shm` (16 GiB) resolution move into the SDK. |
| Know whether my work finished successfully. | Wait on the create operation (`operation.wait()` + `operation.sync_wait()`), extract `operation.resource_id`, loop on `client.get(GetJobRequest(id=job_id)).wait()`, check `TERMINAL_STATES`, sleep between polls, and close the SDK in `finally: sdk.sync_close()`. | Call `run.wait()` and check `run.status != "COMPLETED"`. | Polling loop, terminal-state set, operation waiting, and client teardown move out of customer code. |
| Run several GPU computations without rebuilding cloud integration. | Repeat `shlex.quote` argument formatting, `CreateJobRequest` construction, volume mount protobuf objects, and bounded polling loops across all three inputs. | Reuse `ns.Job(..., volumes=["s3://...:rw"]).create()` and `run.wait(timeout=5400)` in a loop with the identical worker and S3 report verifier. | Orchestration drops from 95 lines to 28 lines (70.5% reduction) while workload, S3 retrieval, and validation remain identical (251 lines). |
| Adapt the example to my workload. | Locate the corresponding nested protobuf fields across `JobSpec`, `DiskSpec`, and `VolumeMount`. | Edit top-level `Job(...)` arguments (`command`, `image`, `gpu`, `timeout`, `volumes`, `disk`, `pricing`). | Measured via the follow-up adaptation protocol in Panel 6 (`Pending study`). |

#### Before — Official Nebius SDK (`examples/official/quickstart.py`, 58 orchestration lines / 61 total lines)

```python
import time
from datetime import timedelta
from uuid import uuid4

from nebius.aio.cli_config import Config
from nebius.api.nebius.ai.v1 import (
    CreateJobRequest,
    GetJobRequest,
    JobServiceClient,
    JobSpec,
)
from nebius.api.nebius.common.v1 import ResourceMetadata
from nebius.api.nebius.compute.v1 import DiskSpec as ComputeDisk
from nebius.sdk import SDK

TERMINAL_STATES = frozenset(
    {"COMPLETED", "FAILED", "CANCELLED", "ERROR"}
)
POLL_SECONDS = 1.0

# Inside main():
config = Config()                                      # SDK reads CLI profile
project_id = config.parent_id
if not isinstance(project_id, str) or not project_id.strip():
    raise RuntimeError("Nebius profile has no parent_id configured")
sdk = SDK(config_reader=config, parent_id=project_id)  # SDK manages lifecycle
try:
    client = JobServiceClient(sdk)
    request = CreateJobRequest(                        # SDK builds request
        metadata=ResourceMetadata(
            parent_id=project_id,
            name=f"job-{uuid4().hex[:12]}",            # SDK generates name
        ),
        spec=JobSpec(
            image="nvidia/cuda:13.1.1-runtime-ubuntu24.04",
            container_command="nvidia-smi",
            platform="gpu-h100-sxm",                   # SDK resolves gpu="h100"
            preset="1gpu-16vcpu-200gb",
            timeout=timedelta(seconds=3600),           # SDK parses timeout="1h"
            shm_size_bytes=16 * 1024**3,               # SDK applies 16Gi default
            disk=JobSpec.DiskSpec(                     # SDK applies 250Gi default
                type=ComputeDisk.DiskType.NETWORK_SSD,
                size_bytes=250 * 1024**3,
            ),
        ),
    )
    operation = client.create(request).wait()          # SDK awaits acceptance
    operation.sync_wait()
    job_id = operation.resource_id
    if not isinstance(job_id, str) or not job_id:
        raise RuntimeError("Create operation returned no job ID")
    print(job_id)
    while True:                                        # SDK polls GetJob
        job = client.get(GetJobRequest(id=job_id)).wait()
        state = job.status.state.name
        if state in TERMINAL_STATES:
            break
        time.sleep(POLL_SECONDS)
    if state != "COMPLETED":
        raise RuntimeError(f"{job_id}: {state}")
finally:
    sdk.sync_close()                                   # SDK closes transport
```

```python
# quickstart_worker.py (deployed inside container image)
import subprocess
import runpod

def run_nvidia_smi() -> str:
    completed = subprocess.run(
        ["nvidia-smi"], check=True, text=True, stdout=subprocess.PIPE
    )
    return completed.stdout

def handler(job: dict[str, object]) -> dict[str, str]:
    del job
    return {"stdout": run_nvidia_smi()}

if __name__ == "__main__":
    runpod.serverless.start({"handler": handler})
```

```python
# quickstart_client.py (local caller against pre-deployed endpoint)
import os
import runpod

def main() -> None:
    runpod.api_key = os.environ["RUNPOD_API_KEY"]
    endpoint = runpod.Endpoint(os.environ["RUNPOD_ENDPOINT_ID"])
    job = endpoint.run({"command": "nvidia-smi"})
    print(job.job_id)
    output = job.output(timeout=3600)
    status = job.status()
    if status != "COMPLETED":
        raise RuntimeError(f"{job.job_id}: {status}")
    if not isinstance(output, dict):
        raise RuntimeError(f"Expected dict output, got {type(output)!r}")
    stdout = output.get("stdout")
    if not isinstance(stdout, str) or not stdout.strip():
        raise RuntimeError("nvidia-smi returned empty output")
    print(stdout, end="")
```

### Key Cross-Platform Differences (Quickstart)

- **Command recipe vs. remote Python function:** `nebius_serverless` runs `["nvidia-smi"]` directly as the container command (`15` total Python lines) without needing a `subprocess.run` wrapper inside Python, whereas Modal (`18` lines) and RunPod (`20` and `34` lines) wrap `subprocess.run(["nvidia-smi"])` inside a Python function or handler.
- **Completion status vs. returned stdout:** Modal and RunPod return `nvidia-smi` stdout directly to the caller in Python. Nebius confirms `run.status == "COMPLETED"` in Python and requires `nebius ai job logs <id>` to inspect container stdout.
- **Hidden deployment work in RunPod Endpoint SDK:** Looking at `quickstart_client.py` alone (`19` lines) would hide `quickstart_worker.py` (`15` lines), `Dockerfile` (`8` lines), `requirements.txt` (`1` line), `docker build` + `docker push`, and endpoint creation in the RunPod console.

#### Before — Official Nebius SDK (`examples/official/matrix_multiply.py`, 95 orchestration lines / 346 total lines)

```python
import shlex
from datetime import timedelta
from nebius.aio.cli_config import Config
from nebius.api.nebius.ai.v1 import (
    CreateJobRequest,
    GetJobRequest,
    JobServiceClient,
    JobSpec,
)
from nebius.api.nebius.common.v1 import ResourceMetadata
from nebius.api.nebius.compute.v1 import DiskSpec as ComputeDisk
from nebius.sdk import SDK

WAIT_SECONDS = 5400
POLL_SECONDS = 1.0
TERMINAL_STATES = frozenset(
    {"COMPLETED", "FAILED", "CANCELLED", "ERROR"}
)

# Inside main():
config = Config()
project_id = config.parent_id
if not isinstance(project_id, str) or not project_id.strip():
    raise SystemExit("Nebius profile has no parent_id configured")
sdk = SDK(config_reader=config, parent_id=project_id)
try:
    client = JobServiceClient(sdk)
    jobs: list[tuple[int, str]] = []
    for size in SIZES:
        args = " ".join(
            shlex.quote(part)
            for part in ("-c", WORKER, prefix, str(size))
        )
        request = CreateJobRequest(
            metadata=ResourceMetadata(
                parent_id=project_id,
                name=f"job-{uuid4().hex[:12]}",
            ),
            spec=JobSpec(
                image=IMAGE,
                container_command="python",
                args=args,
                platform="gpu-h100-sxm",
                preset="1gpu-16vcpu-200gb",
                timeout=timedelta(seconds=3600),
                shm_size_bytes=16 * 1024**3,
                disk=JobSpec.DiskSpec(
                    type=ComputeDisk.DiskType.NETWORK_SSD,
                    size_bytes=250 * 1024**3,
                ),
                volumes=[
                    JobSpec.VolumeMount(
                        source=f"s3://{BUCKET}",
                        container_path="/data",
                        mode=JobSpec.VolumeMount.Mode.READ_WRITE,
                    )
                ],
            ),
        )
        try:
            operation = client.create(request).wait()
            operation.sync_wait()
        except Exception as exc:
            raise SystemExit(
                f"size {size}: submission failed: {exc}"
            ) from exc
        job_id = operation.resource_id
        if not isinstance(job_id, str) or not job_id:
            raise SystemExit(
                f"size {size}: submission returned no job ID"
            )
        jobs.append((size, job_id))
        print(f"size {size}: {job_id}", flush=True)

    rows: list[dict[str, object]] = []
    for size, job_id in jobs:
        wait_deadline = time.monotonic() + WAIT_SECONDS
        while True:
            try:
                job = client.get(GetJobRequest(id=job_id)).wait()
            except Exception as exc:
                raise SystemExit(
                    f"size {size}: job {job_id}: {exc}"
                ) from exc
            state = job.status.state.name
            if state in TERMINAL_STATES:
                break
            remaining = wait_deadline - time.monotonic()
            if remaining <= 0:
                raise SystemExit(
                    f"size {size}: job {job_id}: local wait timed "
                    f"out after {WAIT_SECONDS}s"
                )
            time.sleep(min(POLL_SECONDS, remaining))
        if state != "COMPLETED":
            raise SystemExit(
                f"size {size}: job {job_id} ended {state}"
            )
        rows.append(_fetch_report(size, job_id, prefix))
finally:
    sdk.sync_close()
```

```python
import nebius_serverless as ns

GPU = "h100"
TIMEOUT = "1h"

# Inside main():
runs: list[tuple[int, ns.Run]] = []
for size in SIZES:
    try:
        run = ns.Job(
            ["python", "-c", WORKER, prefix, str(size)],
            image=IMAGE,
            gpu=GPU,
            timeout=TIMEOUT,
            volumes=[f"s3://{BUCKET}:/data:rw"],
        ).create()
    except Exception as exc:
        raise SystemExit(
            f"size {size}: submission failed: {exc}"
        ) from exc
    runs.append((size, run))
    print(f"size {size}: {run.id}", flush=True)

    try:
        # Local observation only. This does not stop the remote job.

    except Exception as exc:
        raise SystemExit(f"size {size}: job {run.id}: {exc}") from exc
    if run.status != "COMPLETED":
        raise SystemExit(
            f"size {size}: job {run.id} ended {run.status}"
```

```python
    runpod.serverless.start({"handler": handler})
```

| Dimension | Nebius (`nebius` & `nebius_serverless`) | Modal (`modal==1.6.3`) | RunPod App SDK Beta (`2.0.0rc1`) | RunPod Endpoint SDK (`2.0.0rc1`) |
| --- | --- | --- | --- | --- |
| **Submission & parallelism** | Explicit loop calling `Job.create()` 3 times before waiting. Each call provisions an isolated single-run job container. | `run_matrix_multiply.map(SIZES)` dispatches across an autoscaling container pool; warm containers may reuse state across inputs. | `run_matrix_multiply.spawn(size)` enqueues all 3 items onto a queue endpoint before `job.result(timeout=3600)`. | `endpoint.run({"size": size})` enqueues all 3 items onto a pre-deployed endpoint before `job.output(timeout=3600)`. |
| **Worker code delivery** | Passed explicitly as `["python", "-c", WORKER, ...]` on a pre-built PyTorch digest image. | Local Python module is serialized/mounted automatically by `modal run`. | Local function is packaged and synced automatically by `rp flash dev`. | Packaged manually into a Docker image (`Dockerfile` + `docker push`). |

## Panel 6: Product Implications and Next Priorities

### 1. What the Current Cloud Jobs Slice Already Solves

- **79.3% reduction in quickstart orchestration (58 → 12 lines)** and **70.5% reduction in batch orchestration (95 → 28 lines)** by moving profile resolution, regional GPU alias mapping (`gpu="h100"` → `gpu-h100-sxm` / `1gpu-16vcpu-200gb`), default disk/shm sizing (`250Gi` / `16Gi`), POSIX command quoting, volume mount parsing (`s3://bucket:/data:rw`), operation acceptance waiting, and `GetJobRequest` polling into `ns.Job` and `ns.Run`.
- **Zero extra wrapper overhead for container commands:** For container-command workloads like `["nvidia-smi"]`, `nebius_serverless` (`15` total lines) is as compact as Modal (`18` lines) and RunPod App SDK (`20` lines).

### 2. Where Customer Friction Remains Visible

Look at the Batch comparison between Designed Nebius SDK (`279` total lines; `28` orchestration + `251` workload/data) and Modal (`126` total lines; `11` orchestration + `115` workload/data) or RunPod App SDK (`132` total lines; `15` orchestration + `117` workload/data):

- **Result transport and storage plumbing (~120 lines in both Nebius batch scripts):** Because Nebius AI Jobs executes a container command and does not expose a small structured return-value channel or Python log/output API, the caller must configure an Object Storage bucket, mount `s3://<bucket>:/data:rw`, write JSON inside the worker, shell out to `aws s3 cp`, classify missing-object vs. access stderr markers, and bound retries for eventual visibility.
- **Worker code delivery (~18 lines in `WORKER`):** Without local source packaging or function serialization, the Python script must embed `WORKER` as a raw string passed to `python -c` (or build and push a custom container image like the RunPod Endpoint track).
- **Log inspection:** Inspecting `nvidia-smi` output requires switching from Python to `nebius ai job logs <id>`.

### 3. Proposed Example and Documentation Recommendations

- **Keep first-run quickstart focused; separate lifecycle operations (Proposal):** [`examples/comparison/quickstart.py`](../examples/comparison/quickstart.py) isolates `Job` → `create()` → `print(run.id)` → `wait()` → `status == "COMPLETED"`. [`examples/job_quickstart.py`](../examples/job_quickstart.py) remains unchanged as the Cloud Jobs contract recipe (which also calls `run.get()`, `run.cancel()` after `wait()`, and `ns.jobs.get()`). In future documentation revisions, `get()`, reattachment, and live cancellation of an active job should live in a dedicated lifecycle recipe rather than the first-run quickstart.

### 4. Future / Proposed SDK Capabilities (Not in the Current Cloud Jobs Slice)

All items below are **future/proposed designs** and are intentionally absent from `src/nebius_serverless` in this slice:

- **Proposed — Small structured result return / log retrieval:** Allowing a job or function to return a small JSON-serializable summary (or fetch container stdout from Python) would eliminate the ~120-line AWS CLI + S3 mount retrieval harness for summary-producing tasks.
- **Proposed — Function decorators and source delivery (`@app.function` / source mounts):** Decorating a local Python function (`matrix_multiply`) and delivering the module automatically would remove embedded `python -c` strings while preserving explicit container image pinning.
- **Proposed — Collection execution (`.map()` / batch controller):** Modal's `.map()` and RunPod's `.spawn()` highlight convenient fan-out collection APIs. Before introducing a Nebius `.map()`, the product contract must explicitly define admission/concurrency limits, ordering guarantees, partial-failure reporting, cancellation semantics for sibling jobs, and retry/recovery behavior.

### 5. Onboarding and Adaptation Study Protocol (`Pending study`)

To test whether the 70.5%–79.3% orchestration reduction translates into faster time-to-first-result and fewer mistakes, run the two-part developer study defined in [`specs/sdk_copmarison.md`](../specs/sdk_copmarison.md):

1. **First-run timing (two cohorts: unconfigured account vs. pre-configured credentials/storage):** Record time to accepted execution, time to confirmed completion, and time to verified output (`nebius ai job logs <id>` for quickstart; 3 validated table rows for batch), separating hands-on authoring/setup time from cloud provisioning and image pull duration.
2. **Adaptation task:** Ask participants to modify both Official and Designed Nebius scripts to add a fourth matrix size (`3072`) or change the diagnostic command, recording lines changed, completion time, documentation lookups, and failed attempts.
